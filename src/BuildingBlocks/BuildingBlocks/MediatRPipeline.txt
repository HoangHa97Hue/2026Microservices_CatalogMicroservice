when face a new feature/framework:
-Instead of asking "what is this syntax"

try:
+ What problem its trying to solve?
+ What pattern is it trying to implement?
+Tradeoff:
+Goals
+Benefits

for example: 
CQRS(Mediator) pipeline behavior:

-Problem: (duplicated cross-cutting concerns) We have cross cutting concerns that we want to apply to all our handlers (ex: logging, validation, performance monitoring, etc) 
-Pattern: middleware + decorator
-Goal: separator of concerns, single responsibility principle, open/closed principle
-Benefits: maintainable code, scalibility

về bản chất , CQRS pipeline behavior là một implementation của pattern middleware + decorator.

Ví dụ NestJS:

@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler) {

    console.log("Before");

    return next.handle().pipe(
      tap(() => console.log("After"))
    );
  }
}


MediatR
public async Task<TResponse> Handle(
    TRequest request,
    RequestHandlerDelegate<TResponse> next)
{
    Console.WriteLine("Before");

    var response = await next();

    Console.WriteLine("After");

    return response;
}

GOlang

Đây là handler gốc
func Hello(w http.ResponseWriter, r *http.Request) {
    fmt.Fprintf(w, "hello")
}

Giờ ta viết Logging decorator
func Logging(next http.HandlerFunc) http.HandlerFunc {

    return func(w http.ResponseWriter, r *http.Request) {

        fmt.Println("Before")

        next(w, r)

        fmt.Println("After")
    }
}

 Dùng thế này
http.HandleFunc("/", Logging(Hello))

+ Flow thực tế
Request
 -> Logging
     -> Hello


Giờ nhìn lại:
Logging(Hello)

Nó chính là:

    Original
